🧠 Misconceptions Corrected

Is the tokenizer a word → number dictionary?

❌ Misconception
What I thought:
The tokenizer is like a dictionary: "The" → 464, "cat" → 3290, etc.
The correction:
The dictionary is the output, not the input. The real work is: text → bytes → apply learned merges in rank order → lookup.
Key: Byte-Pair Encoding (BPE) is a learned compression algorithm. The "dictionary" emerges from counting and merging the most frequent byte pairs. Different models have different vocabularies because they trained on different data.

Is the token vector provided by the tokenizer?

❌ Misconception
What I thought:
The tokenizer outputs both an ID and a vector (like a 768-dimensional embedding).
The correction:
The tokenizer outputs only an ID (an integer). The vector is produced by the model via a learned lookup table E[id].
Key: The tokenizer is frozen before training. It's a fixed compression scheme. The model learns what each token means by training the embedding table E, which maps token IDs to vectors.

Is position encoding optional?

❌ Misconception
What I thought:
Maybe the model can figure out order from context alone. Position might be extra.
The correction:
Attention is permutation-equivariant: shuffle the input tokens and outputs shuffle identically. Without position, "dog bites man" = "man bites dog". Position encoding is non-negotiable.
Key: Every modern LLM injects position info. The scheme varies (learned table, sinusoids, RoPE), but every model does it somewhere.

💡 Key Definitions & Clarifications

What does "frozen" mean?

✓ Clarification
Frozen weights = parameters that don't change during training. The tokenizer is frozen (locked before training starts). The embedding table is not frozen (it's learned during training).
Key: If you change the tokenizer after training starts, you must retrain the embedding table, because the rows of E are indexed by token IDs.

Why is the residual stream a matrix, not a vector?

✓ Clarification
The residual stream has shape (T, d_model) where T is sequence length. There's one d_model-dimensional vector per token position. Attention routes info between positions; MLP works per-position independently.
Key: This is why the model scales: you can have 10 tokens or 2048 tokens flowing through the same block structure. The shape is flexible in the sequence dimension.

Why do residual connections prevent vanishing gradients?

✓ Clarification
Without residuals: gradients multiply through 80 layers: g ≈ 0.9^80 ≈ 10^-4 (dead). With residuals: gradients add through a direct path: g ≈ 1 + small terms (alive).
Key: The identity shortcut (the + in x = x + f(x)) creates a highway for gradients. Early layers can receive strong signals even if intermediate layers are noisy.

What's the difference between a tensor and a weight?

ℹ Definition
Tensor: data flowing through the model (token IDs, embeddings, attention scores). Weight: learned parameters (matrices that get updated during training). In code: tensors are temporary; weights are persistent.
Key: During inference, weights never change. You compute forward pass (tensors flow), sample a token, feed it back. Weights stay frozen.

What's LayerNorm and why is it needed?

ℹ Definition
LayerNorm: normalizes vectors to have mean=0 and std=1. Applied before attention and MLP (before → instead of after ↪ in transformers). Why: keeps values in sane range so downstream layers see stable scale. Without it, early layers' outputs can grow unbounded, saturating later layers.
Key: LN is not a learner of features; it's a stabilizer. It keeps the residual stream from exploding or vanishing.

What's the difference between attention heads?

ℹ Definition
Multi-head attention splits the d_model dimensions into num_heads separate "heads", each computing attention independently on a smaller dimension space, then concatenating. GPT-2 has 12 heads of dimension 64 (12 × 64 = 768).
Key: Heads allow parallelism and let the model learn multiple types of interactions (some heads look for syntax, others for semantics, etc.). But they're not "semantic roles"—the model learns what each head does.

❔ Questions Asked During Learning

Can the embedding table have the same vector for two different tokens?

Question
Technically yes, but in practice no. During training, if two tokens always appear in the same contexts, their gradients would be identical, so their rows would update identically. Over many steps they'd drift to the same vector. But the model would then lose information—it couldn't distinguish them. The loss function would punish this (can't predict well if you can't tell tokens apart), so training pushes tokens toward different vectors.

Why does attention use sqrt(d_head) instead of just dividing by d_head?

Question
If Q and K are both drawn from Gaussian distributions with variance 1, then their dot product has variance d_head. To keep the variance of the dot product at 1 (for stable softmax), you divide by sqrt(d_head). This prevents the logits from getting too large or too small, keeping softmax well-behaved.

Why is MLP 8·d² parameters vs. Attention's 4·d²?

Question
Attention has 4 projections: Q, K, V, and Output (each d_model → d_model) = 4·d². MLP has: up-projection (d_model → 4·d_model) and down-projection (4·d_model → d_model) = d·4d + 4d·d = 8·d². MLP is bigger because of the 4× expansion (standard in transformers).

Why is a nonlinearity (ReLU/GELU) needed in MLP?

Question
Without it, the two linear projections would collapse into one: (x·W_up)·W_down = x·(W_up·W_down) — just a single linear transformation. The nonlinearity breaks this, letting the network learn non-linear functions. The MLP becomes a learned, learnable nonlinear feature processor.
